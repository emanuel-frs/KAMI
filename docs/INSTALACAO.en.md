# Installing Kami

*[Português](./INSTALACAO.md)*

Kami is a local-first desktop app. The backend and the SQLite database
run on your computer; no remote service is needed to use the app. It only
goes online when you turn on GitHub, e-mail or search (full list in the
[README](../README.en.md#privacy-what-leaves-your-computer)). The official
installers are on the [Releases page](https://github.com/emanuel-frs/KAMI/releases/latest)
and on the [download page](./index.html).

## Linux

Releases published by the repository workflow include, for x86_64,
these assets:

| Distribution/format | Asset |
|---|---|
| Debian, Ubuntu and derivatives | `kami-<version>-linux-amd64.deb` |
| Fedora, RHEL and derivatives | `kami-<version>-linux-x86_64.rpm` |
| Any compatible distribution | `kami-<version>-linux-x86_64.AppImage` |
| Arch and derivatives, with `makepkg` | `kami-<version>-PKGBUILD` and the `.deb` package verified by the recipe |

The asset names are part of the install contract. The `SHA256SUMS` file
published alongside them lists each installer by its exact name; check it
before installing by hand. `scripts/install.sh` downloads the official
release and verifies the SHA-256 before handing the package to the package
manager or installing the AppImage.

Old releases may use names generated by Tauri and may not include
`SHA256SUMS`; the installer aborts in that case instead of installing an
unverified file. The download page still shows old installers when they
exist, but doesn't offer verified install commands for them.

To use the installer from a clone of the repository:

```sh
git clone https://github.com/emanuel-frs/KAMI.git
cd KAMI
sh scripts/install.sh --dry-run
sh scripts/install.sh
```

The installer detects Debian/Ubuntu, Fedora/RHEL and Arch. On other
Linux systems it installs the AppImage at `~/.local/bin/kami` and creates
a shortcut in `~/.local/share/applications/`. On Arch, run it as a normal
user: `makepkg` can't run as root. If `makepkg` isn't installed, the
installer uses the AppImage.

Available options:

```sh
sh scripts/install.sh --version 1.8.1
sh scripts/install.sh --uninstall
sh scripts/install.sh --uninstall --apagar-dados
sh scripts/install.sh --help
```

`--uninstall` removes the package or AppImage and what Kami left in your
home folder (start with the system and the launcher with the colored
icon), but keeps your data. With `--apagar-dados` it also erases the data,
the screen cache and the password key in the system keyring — it asks you
to type `apagar` first. On Linux, data lives in `$XDG_DATA_HOME/kami` or,
when `XDG_DATA_HOME` isn't set, in `~/.local/share/kami`.

Removed the package straight through `apt`/`dnf`/`yay`, without the
script? Kami no longer shows up in the menu or tries to open at login (the
entries it left in your home folder turn themselves off once the program
is gone), and the leftover files are listed in
[Removing everything by hand](#removing-everything-by-hand).

### Fonts for Chinese, Japanese, Korean and Hindi

Kami uses the system fonts. Most distributions already ship them; on a
minimal install, text in these languages may show up as empty boxes — the
app warns you and shows the package. The `.deb` and `.rpm` recommend the
fonts, and the PKGBUILD lists them as optional:

```sh
sudo dnf install google-noto-sans-cjk-fonts google-noto-sans-devanagari-fonts   # Fedora
sudo apt install fonts-noto-cjk fonts-noto-core                                  # Debian/Ubuntu
sudo pacman -S noto-fonts-cjk noto-fonts                                         # Arch
```

### Manual install and verification

Download the right asset and the `SHA256SUMS` from the same Release. In
your downloads folder, verify the manifest before installing:

```sh
sha256sum --ignore-missing --check SHA256SUMS
```

Then use your distribution's package manager to install the `.deb` or
`.rpm`, or make the AppImage executable and open it. For Arch, use the
versioned `PKGBUILD` from the Release and follow its verification with
`SHA256SUMS`. Don't install a file whose checksum doesn't match.

## Windows

Download `kami-<version>-windows-x64-setup.exe` from the Releases page and
run the installer. NSIS is set up to install into the current user's
profile, without asking for administrator rights. WebView2 uses Tauri's
default `downloadBootstrapper`: if the runtime isn't available, the
installer fetches Microsoft's official bootstrapper; that may need an
internet connection.

### Unsigned Windows installer

The installer isn't signed yet: code signing for Windows costs money and
Kami is a personal project. In practice, Windows may show warnings like
"unknown publisher" or even say the file may be malicious. New, unsigned
programs with few downloads often hit this, and this one also bundles a
Python backend packaged with PyInstaller, a format antivirus tools
sometimes flag by mistake (false positive). **That doesn't prove the file
is safe, nor that it's dangerous**: so check where it came from before
trusting it.

Before running it:

1. Download the installer only from this repository's [Releases page](https://github.com/emanuel-frs/KAMI/releases/latest).
2. Compare the hash in PowerShell, in the download folder:
   `Get-FileHash .\kami-<version>-windows-x64-setup.exe -Algorithm SHA256`.
   The right value is printed on the Release page itself, just below the
   file table (and on that file's line in `SHA256SUMS`).
3. For a second opinion, upload the file to VirusTotal. Some engines may
   flag a false positive on unsigned executables.
4. The source code is in this repository and the installer is built by
   the public [`release.yml`](../.github/workflows/release.yml) workflow.

If you decided to trust the file, on the SmartScreen screen the usual flow
is **More info → Run anyway**. If Microsoft Defender blocks it or puts it
in quarantine, go to **Windows Security → Virus & threat protection →
Protection history**, where the detection can be allowed on the device.
Only do that if the origin and the hash check out.

**Smart App Control** (Windows 11) is stricter: it blocks unsigned apps and
offers no "run anyway". With it on, Kami won't install on that machine —
don't turn the protection off just for this. There are no plans for
signing: the free option requires an open-source license, and Kami doesn't
use a paid certificate, so the SmartScreen warning keeps showing up with
every version, including when you update from inside the app.

### Uninstalling and kept data

Use **Windows Settings → Apps → Installed apps** to remove Kami. The
uninstaller removes the shortcuts and the start-with-system entry. Your
data (`%APPDATA%\kami`) stays, unless you tick **"Remove program data"** —
then the data, the automatic copies and the password key in Credential
Manager go too. To uninstall without questions: `uninstall.exe /S` (keeps
the data) or `uninstall.exe /S /APAGARDADOS`, in Kami's folder
(`%LOCALAPPDATA%\Kami`).

## Removing everything Kami put on this computer

Done using Kami on this machine? In **settings › backup and data › remove
everything kami put on this computer** the app itself erases, after you
confirm twice: your data, the automatic copies, the password key in the
system keyring, the start-with-system entry, the colored icon in the
launcher/shortcuts and the screen cache — and closes. Export a backup
first if you want to keep anything (the button is right there). What
stays: the **extra folder** for copies, if you set one up (it's your copy
outside the computer), and the **program** — on Windows the uninstaller
opens at the end; on Linux remove the package (`sudo apt remove kami`,
`sudo dnf remove kami`, `yay -R kami-bin`) or delete the AppImage.

### Removing everything by hand

What Kami creates outside the program folder:

| What | Linux | Windows |
|---|---|---|
| data (database, copies, log, colored icons) | `~/.local/share/kami` | `%APPDATA%\kami` |
| screen cache and storage | `~/.local/share/com.kami.app`, `~/.cache/com.kami.app` | `%APPDATA%\com.kami.app`, `%LOCALAPPDATA%\com.kami.app` |
| start with the system | `~/.config/autostart/Kami.desktop` | registry: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `Kami` |
| colored icon in the menu | `~/.local/share/applications/Kami.desktop` (only if it has `X-Kami-IconeTema`) | `Kami.lnk` shortcuts (go away with the program) |
| password key | Secret Service/KWallet: service `kami`, user `chave-dos-segredos-…` | Credential Manager: `kami`, user `chave-dos-segredos-…` |
| copies in the extra folder | the folder you chose (`kami-semanal-*.db`) | same |

For the password key, delete only the one for user
`chave-dos-segredos-…` — other entries of the `kami` service (from a demo
folder, for example) belong to another data folder.

## Updating

Kami tells you in the bell when a new version comes out — it **never
downloads or installs anything on its own**. To find out, it only checks
the list of versions on the Releases page (on launch and once a day); you
can turn that off in settings › about › "check for updates", which also
has "check now".

- **Windows**, **AppImage** and **`.rpm`**: "update now" (in the bell or in
  settings › about) keeps a copy of the database
  (`backups/kami-antes-de-atualizar-…`), downloads the new version, checks
  the update signature and installs it; Kami closes and reopens already
  updated. With the `.rpm` the system asks for your password at that point
  (pkexec). On Windows SmartScreen may show "unknown publisher" again —
  it's the same warning as at install time (see
  [Unsigned Windows installer](#unsigned-windows-installer)).
- **`.deb` and AUR**: the notice shows up the same way, but the system's
  package manager does the updating (download the new package from the
  Release and install it over the old one, or `yay -Syu` on Arch). Your
  data stays.

**Updating the `.rpm` on its own (optional).** If you'd rather not think
about it, you can install a system service that checks for the latest
version when the computer starts and once a day, checks the SHA-256
published by GitHub and installs with `dnf` — without asking:

```sh
sudo bash scripts/atualizar-rpm.sh instalar   # to undo: ... remover
```

Notices for test versions (`2.0.0-rc.1`, for example) don't show up: only
published versions.

## Data, logs and diagnostics

| System | Data and log |
|---|---|
| Windows | `%APPDATA%\kami`; log at `%APPDATA%\kami\kami-backend.log` |
| Linux | `$XDG_DATA_HOME/kami` or `~/.local/share/kami`; log at `kami-backend.log` inside that folder |

If the backend doesn't start or crashes, Kami shows a bar at the top with
the reason, tries to restart it on its own and offers **restart** and
**open log folder**. Attach `kami-backend.log` to the problem report in
the repository. Before sharing, review the file and remove any personal
information you don't want to publish.

When something goes wrong on Kami's side, a red notice shows up with a
code (e.g. `code #k7f2a9`) and a **copy details** button. The same code is
on the error's line in `kami-backend.log`. Paste the details into the
report to find the problem fast. Errors in the screen itself go to the log
too, as `[app.frontend]`.

Each log line starts with the local date and time (e.g.
`2026-10-17 16:42:07.684-03:00 INFO [uvicorn.error] ...`), so you can find
the part from the moment the problem happened. Past 1 MB, the current log
becomes `kami-backend.log.old` and a new one starts. Request addresses are
logged without their parameters (`?busca=...`), so searches and filters
aren't written to disk.

### What's in the data folder

| File | What it is |
|---|---|
| `kami.db` (and `kami.db-wal`, `kami.db-shm`) | all your data |
| `backups/` | automatic copies of the database: weekly (the last 4), before big actions — import, erase everything, reset the key, restore, update the app — (the last 5) and before migrating the database to a new version (the last 3) |
| `kami-backend.log` (and `.old`) | the backend log |
| `backend_port.txt`, `backend_token.txt` | port and token of the current run; recreated on every launch |
| `pin.json` | only with the PIN on: the hash of the PIN and of the recovery code |
| `.secret_key_no_cofre` | marker that the key for saved passwords is in the system keyring (no secret in it) |
| `.secret_key` | only on systems without a keyring: the key for saved passwords |

**Forgot the PIN.** On the lock screen, use "forgot the PIN" with the
recovery code shown when the PIN was turned on. Without the code: close
Kami and delete `pin.json` from that folder. Next time it opens without a
PIN, with all your data — the PIN protects opening the app, it doesn't
encrypt the database.
